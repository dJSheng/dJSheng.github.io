知识小课堂：float 与 position 的区别

这两个布局方式是传统 CSS 布局的两大基石，理解它们是本项目的核心：

float 浮动

让元素"飘"到左侧或右侧，后续元素会流过来填补空间。适合一行内多个元素横向排列（如导航菜单、卡片网格）。

float: left; → 元素靠左排列，后面的内容自动靠右流动
float: right; → 元素靠右排列
position 定位

精确控制元素在页面中的坐标位置。适合精确定位、层叠覆盖（如横幅装饰图案、三卡片重叠排列）。

position: relative; → 相对定位（作为参照物）
position: absolute; → 绝对定位（相对于最近的 relative 父元素）

  • 技术栈：HTML5 + CSS3（外部文件）+ Font Awesome 图标库
  • float 适合横向排列，position 适合精确定位与层叠

知识小课堂：语义化标签

HTML5 提供了一系列有语义含义的标签，相比通用的 <div>，它们能让代码结构更清晰，也对搜索引擎和无障碍阅读更友好：

<nav> → 导航区域
<section> → 页面中的一个内容区块
<footer> → 页脚区域
<div> → 通用容器（没有特定语义，用于布局分组）

本项目中的选择原则：导航用 nav，内容板块用 section，页脚用 footer，其余布局容器用 div。

易错点提醒
忘记写 <!DOCTYPE html> 会怎样？
浏览器可能进入"怪异模式"（Quirks Mode），导致部分 CSS 表现异常。必须在第一行声明 DOCTYPE。
class 属性可以写多个值吗？
可以！用空格分隔，如 class="main-nav w clearfix" 表示元素同时拥有三个类名。CSS 中任何一个类选择器都能匹配到它。
本节小结
  • HTML 文档由 DOCTYPE、html、head、body 四部分组成
  • 使用语义化标签：nav、section、footer 提升代码可读性
  • class 属性支持多类名（空格分隔），可同时应用多个样式
  • 页面结构从上到下：横幅 → 导航 → 内容板块 → 页脚

  • 理解 CSS Reset（全局重置）的作用与原理

步骤一：全局重置

在 style.css 的最顶部写入以下代码，消除所有浏览器默认的内外边距：

CSSstyle.css 开头
/* ---------- 1. 全局重置与基础样式 ---------- */
* {
    margin: 0;
    padding: 0;
    box-sizing: border-box;
}
代码解释
*通配选择器，匹配页面上所有 HTML 元素
margin: 0清除所有元素的外边距（不同浏览器默认值不一致）
padding: 0清除所有元素的内边距
box-sizing: border-box让元素的 width/height 包含 padding 和 border，简化尺寸计算
知识小课堂：盒模型与 box-sizing

每个 HTML 元素都是一个"盒子"，由四层组成（从内到外）：

margin（外边距）→ border（边框）→ padding（内边距）→ content（内容区）
不设 box-sizing（默认 content-box）：

你写的 width: 280px 只包含内容区，加上 padding 和 border 后实际宽度会变大，容易超出预期导致布局错位。

设了 box-sizing: border-box：

你写的 width: 280px 就是最终占据的宽度，padding 和 border 向内挤压内容区，计算更直观。

假设 width:280px、padding:10px、border:5px：
content-box → 实际宽度 = 280 + 10×2 + 5×2 = 310px（超了！）
border-box → 实际宽度 = 280px（内容区自动缩为 250px）

步骤二：body 与基础元素样式

CSS基础样式
body {
    font-family: "Microsoft YaHei", "微软雅黑", Arial, sans-serif;
    color: #333;
    background-color: #faf6f0;
    line-height: 1.6;
}

a {
    text-decoration: none;
    color: inherit;
}

ul, li {
    list-style: none;
}

img {
    display: block;
}
代码解释
font-family: "Microsoft YaHei", ...设置正文字体，优先使用微软雅黑，找不到则降级到 Arial
color: #333正文颜色为深灰色（比纯黑柔和，阅读更舒适）
background-color: #faf6f0页面背景为淡米黄色，呼应传统民俗的温暖色调
line-height: 1.6行高为字号的1.6倍，文字间距舒适不拥挤
a { text-decoration: none }去掉所有超链接默认的下划线
a { color: inherit }链接颜色继承父元素（不使用默认蓝色）
ul, li { list-style: none }去掉列表默认的黑点项目符号
img { display: block }图片转为块级元素，消除底部默认的3px间隙
知识小课堂：为什么 img 要设 display:block？

<img> 是行内元素（inline），默认按照文字基线对齐，会在图片底部产生约 3-4px 的空白间隙，影响布局精度。

设为 display: block 后，图片变为块级元素，底部间隙消失，方便精确控制高度和排列。

易错点提醒
不写全局重置会有什么问题？
不同浏览器对 h1、ul、p 等标签有不同的默认 margin/padding，不重置会导致页面在不同浏览器中表现不一致，出现难以排查的间距偏差。
font-family 多个字体怎么选？
从左到右依次尝试：用户电脑装了"Microsoft YaHei"就用它，没装就试"微软雅黑"，再没有就用 Arial，最后 sans-serif 兜底。
本节小结
  • 通配符 * 重置所有元素的 margin/padding，消除浏览器差异
  • box-sizing: border-box 让宽度计算更直观
  • body 设置字体、颜色、背景、行高等全局基础样式
  • a 去下划线、ul 去项目符号、img 转块级——三个常见默认值清除

版心与清除浮动工具类
编写 .w 版心和 .clearfix 两个最重要的通用工具类

学习目标

  • 理解"版心"概念及其在网页布局中的作用
  • 掌握 margin: 0 auto 实现水平居中的原理
  • 理解浮动带来的"高度塌陷"问题及 clearfix 解决方案

步骤一：版心工具类 .w

CSS版心
/* 版心：固定宽度并水平居中 */
.w {
    width: 1200px;
    margin: 0 auto;
}
代码解释
width: 1200px内容区域固定宽度 1200px（适合 PC 端标准设计稿宽度）
margin: 0 auto上下外边距为0，左右外边距自动（auto）→ 实现水平居中
知识小课堂：margin: 0 auto 居中原理

auto 的含义是"自动分配剩余空间"。当元素有固定宽度时，浏览器会计算父容器宽度减去元素宽度后的剩余空间，然后平均分给左右外边距。

屏幕宽 1920px，元素宽 1200px
剩余空间 = 1920 - 1200 = 720px
左 margin = 右 margin = 720 ÷ 2 = 360px → 元素居中

注意：只有块级元素且设置了明确 width 时，margin: auto 才能居中。行内元素和没有宽度的块级元素不会生效。

步骤二：清除浮动工具类 .clearfix

CSS清除浮动
/* 清除浮动通用工具类（解决父元素高度塌陷） */
.clearfix::after {
    content: "";
    display: block;
    clear: both;
}
代码解释
::after伪元素，在元素内部最后面插入一个看不见的"虚拟元素"
content: ""虚拟元素的内容为空（必须有 content 属性，伪元素才会生成）
display: block让虚拟元素变成块级元素，独占一行
clear: both清除左右两侧的浮动影响，撑开父元素高度
知识小课堂：浮动高度塌陷问题
问题演示

当一个父容器 <ul> 里面的子元素 <li> 都设�� float: left，子元素会脱离正常文档流。父容器找不到子元素来撑高度，高度变为 0，导致后面的内容"顶上来"，布局全部乱掉。

解决原理

.clearfix::after 在父容器末尾插入一个块级虚拟元素，它不受浮动影响（因为 clear:both），它会占据正常的文档流位置，从而"撑"出父容器的真实高度。

使用方法：给包含浮动子元素的父容器加上 class="clearfix" 即可。
本项目中 nav、ul、footer-content 都需要加 clearfix。
易错点提醒
忘加 clearfix 导致布局塌陷？
错误：没加 clearfix父元素高度为0，背景色/边框不显示，下方元素错位顶上来
正确：加了 clearfix父元素正常包裹浮动子元素，高度和样式正常
content: "" 能省略吗？
不能！content 属性是伪元素生成的必要条件，没有它 ::after 根本不会出现在页面上，即使为空字符串也必须写。
本节小结
  • .w 版心类：固定 1200px 宽 + margin:0 auto 水平居中
  • margin:auto 居中原理：自动平分剩余空间，前提是元素有固定宽度
  • .clearfix::after 通过插入虚拟块级元素 + clear:both 解决高度塌陷
  • 凡是内部有 float 子元素的容器，都要加 clearfix 类

  • cover → 等比例缩放并裁剪，完全填满容器（可能裁掉部分画面）
  • contain → 等比例缩放，完整显示，可能有留白
  • fill → 拉伸变形填满（不推荐，图片会变形）

卡片图片统一用 cover，确保不同��例的图片都能统一高度、完整填充。

忘加 .last 类导致最后一张卡片换行？

错误3张卡片都有 margin-right:26px → 总宽 280×3+26×3=918px > 892px，第三张被挤到第二行
正确第三张加 .last 去掉 margin-right → 总宽 280×3+26×2=892px，正好一行

知识小课堂：left:50% + translateX(-50%) 居中大法

这是 CSS 中最经典的绝对定位居中方案，分两步：

第一步：left: 50%

让元素左边缘移动到父容器的50%位置。但此时元素整体偏右——因为它的左边缘在中间，身体全部在右半边。

第二步：transform: translateX(-50%)

-50% 的参照物是元素自身的宽度（不是父容器！），向左移动自身宽度的一半，正好让元素中心对齐父容器中心。

卡片宽300px，舞台宽1200px：
left:50% → 左边缘在 600px 处
translateX(-50%) → 向左移 150px（300px的一半）
最终左边缘在 450px，右边缘在 750px → 居中
易错点提醒
中间卡片 hover 时向右偏移了？
这是一个非常常见的 bug！中间卡片原本有 transform: translateX(-50%) 来居中，如果 hover 时只写 transform: translateY(-10px)，会覆盖掉原来的 translateX(-50%)，导致卡片向右偏移。
错误写法.card-center:hover { transform: translateY(-10px); }
→ translateX(-50%) 被覆盖，卡片向右偏移
正确写法.card-center:hover { transform: translateX(-50%) translateY(-10px); }
→ 两个变换都保留，既居中又上浮
卡片标题颜色不一样？
这是有意设计的：左卡片 h3 是红色 #c0392b，中间是蓝色 #2980b9，右卡片是绿色 #27ae60——用颜色区分三种文化类型。

中间卡片层级最高（z-index:2），与左右卡片可能有轻微重叠。
悬停时卡片上浮10px、阴影加深、提到最上层。

  • 三张卡片用 position:absolute + left/right 精确定位

一、高频问题排查

常见问题（点击展开）
Q1：卡片排列错位 / 换行不正常？

排查步骤：
1. F12 选中卡片，查看 width 和 margin-right 是否正确
2. 检查每行最后一张是否加了 .last 类
3. 计算列表宽度是否 = 卡片数×卡片宽 + (卡片数-1)×间距
4. 检查是否设了 box-sizing: border-box

Q2：父元素背景/边框消失，下方内容顶上来？

典型的浮动高度塌陷问题。给包含浮动子元素的父容器加上 class="clearfix" 即可解决。

Q3：中间卡片 hover 时向右偏移？

中间卡片用 transform: translateX(-50%) 居中，hover 的 transform 必须保留它：
transform: translateX(-50%) translateY(-10px);

Q4：图片底部有不明间隙？

img 是行内元素，底部有基线对齐间隙。全局 CSS 中已设 img { display: block; } 可解决。

Q5：CSS 修改后页面不变？

浏览器缓存了旧 CSS。按 Ctrl + Shift + R 强制刷新清除缓存。

Q6：Font Awesome 图标不显示？

①检查 CDN link 是否在 head 中；②检查类名拼写（fas fa-home 不是 fa fa-home）；③检查网络连接。

Q7：搜索框 input 和 button 之间有缝隙？

HTML 中两个标签之间的空格/换行被渲染为间距。解决：标签间不留空格，或都用 float:left 紧贴。
